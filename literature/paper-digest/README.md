# 이번 주 논문

매주 **월요일 오전 9시**, 내 연구 분야 논문을 자동으로 받는 시스템.

## 동작 방식

**4개 카테고리**마다: 피인용 상위 2편(🔵) + 최신 1편(🟠) = 매주 12편.

1. **후보 수집** — Europe PMC 에서 카테고리당 200편(피인용 100 + 최신 100). 검색 단계에서 철회·우려표명 논문을 이미 제외한다.
2. **검증** — OpenAlex 로 실측 인용수·FWCI·철회 여부·저널 지표를 보강. NIH iCite 로 RCR 추가.
3. **선별** — 아래 3층 구조.
4. **요약** — 최종 12편에만 유형·방법·결과·연결성을 **로그인된 claude CLI** 로 생성 (API 키 있으면 API 우선).
5. **발송** — 디스코드 웹훅 또는 Gmail. `secrets.env` 에 채운 채널로 전송(둘 다 채우면 둘 다).

#### 인용·저널·신뢰를 한 점수로 섞지 않는다

| 층 | 역할 | 쓰는 신호 |
|---|---|---|
| 1층 **신뢰** | 통과/탈락. 정렬에 관여 안 함 | 철회·우려표명·프리프린트·미래 발행일·이미 보낸 논문 |
| 2층 **선별·정렬** | 무엇이 위로 오는가 | 최신=Claude 관련도 사전선별 / 피인용=FWCI 내림차순 |
| 3층 **표시** | 판단 재료를 보여주고 결정은 사용자 몫 | 실측 인용수·FWCI·분야 백분위·저널 등급·논문유형 |

**저널 지표는 표시 전용이고 필터로 쓰지 않는다.** 2년 평균 피인용은 분야마다 스케일이 달라서(eLife 1.7 < PLoS ONE 3.1 < J Ethnopharmacol 5.3 < Bioinformatics 6.1) 하한선을 걸면 좋은 저널이 먼저 죽는다.

#### 왜 FWCI 로 정렬하나

Europe PMC 의 인용수는 **EPMC 코퍼스 내부 인용만** 세어 실제의 절반 수준이다(Nat Rev Microbiol SCFA 리뷰 = EPMC 209회 vs OpenAlex 415회). 원인용수로 정렬하면 리뷰논문과 큰 분야가 유리하고, 2년 창에서 앞선 해가 뒤엣해를 항상 이긴다. FWCI(field-weighted citation impact)는 **같은 분야·같은 해 논문 평균 대비 몇 배** 인용됐나를 보므로 그 편향이 없다. 인용 5회 미만은 FWCI 가 불안정해 뒤로 보낸다.

#### 후보풀을 100편으로 두는 이유

후보는 Europe PMC 의 **원인용수** 순으로 받아오는데 정렬은 FWCI 로 한다. 풀이 좁으면 이 어긋남 때문에 진짜 상위 논문이 애초에 후보에 못 들어온다 — 실측으로 FWCI 349.8(분야 평균의 350배)인 FMT+면역치료 논문이 원인용수는 54회뿐이라 상위 60위 밖이었고, 풀을 100으로 올려서야 처음 보였다.

#### 한 번 보낸 논문은 다시 안 보낸다 (만료 기간 없음)

매주 새로 검색해도 답은 거의 같다 — 개편 전 시스템이 7월 3일에 보낸 피인용 8편 중 **6편이 7주 뒤에도 그대로** 1·2위였다. "최근 2년 인용 상위"의 순위는 주 단위로 안 바뀌기 때문. 그래서 `history.json` 이 없으면 매주 같은 논문이 온다. (최신 슬롯 4편은 이력 없이도 매주 바뀐다.)

만료 기간은 두지 않는다. **검색 창이 매년 1월에 통째로 갈리므로**(2026년엔 2025~2026년, 2027년엔 2026~2027년) 후보가 해마다 새로 공급된다. 만료 없이 1년치를 시뮬레이션하면 편수 미달 주차가 없고, 47주차부터 아래 안전장치가 몇 편씩 채운다. 파일은 1년에 15KB 늘어난다.

#### 후보가 마르면

편수를 줄이지 않고 **가장 오래 전에 보낸 논문부터** 되살려 채우고, 카드에 `2026-03-02 에 보낸 논문 (후보 부족으로 재등장)` 경고를 붙인다. 신뢰 필터(철회·프리프린트·미래 발행일)는 이때도 절대 풀지 않는다.

## NotebookLM 연동 (`notebook_sync.py`)

논문이 도착한 뒤, PDF 를 NotebookLM 에 올려 **논문별 정리본**과 **논문 1편당 한국어 팟캐스트 1개**를 만들고 옵시디언 주차 노트로 남긴다.

```
월 09:00  weekly_papers.py    → 디스코드 12편
월 오전   내가 PDF 12편을 MM/paper-digest-pdf-drop/ 에   ← 12편 전부 첫날
월 12:00  notebook_sync.py --check   → 빠진 PDF 를 제목까지 찍어 알림
월 12:30  notebook_sync.py    → 노트북·정리본 12편·팟캐스트 6편·주차 노트
매일 10:30·17:00  notebook_sync.py --podcasts-only  → 남은 팟캐스트를 빈 칸만큼
          (다 됐거나 주차 노트가 없으면 10초 안에 조용히 종료)
```

**PDF 는 첫날 12편을 다 넣는다.** 나눠 넣는 건 팟캐스트뿐이다 — 업로드·정리본은 한도가 없고,
소스가 다 올라가 있어야 정리본 12편이 첫날 한 번에 끝난다.

PDF 는 **파일명을 바꾸지 않아도 된다** — `pdftotext` 로 1페이지의 DOI·제목을 읽어 논문에 붙인다. 업로드에 성공한 PDF 만 지우고 실패분은 남겨 다음 주에 재시도한다.

#### 정리 요청서는 코드가 아니라 파일에 있다

`prompts/paper-understanding.md` 하나만 고치면 앞으로 모든 논문에 반영된다. `paper-understanding` · `paper-analysis` 두 스킬에서 이해 관련 규격만 뽑아 조합했다 — Methods 재현 프로토콜(catalog#·농도·온도·SW 버전·QC), 공부 단어장(용어마다 정의·비유·이 논문에서·모르면), 핵심 개념 심층. **비판적 분석은 의도적으로 뺐다**(저자가 밝힌 한계는 남긴다).

논문 1편을 **3콜로 나눠** 묻는다. 한 번에 요구하면 답이 줄거나 중간이 잘린다.

#### 실행 중 배운 것 (같은 함정을 다시 밟지 않도록)

- **`ask` 는 기본이 대화 이어쓰기다.** 12편 × 3콜을 돌리면 이력이 쌓여 응답이 268MB 를 넘고 RPC 가 죽는다 → 논문마다 `--new` 로 대화를 갈고 `-s` 로 그 논문 소스만 본다.
- **NotebookLM 이 "문서를 생성해 두었습니다" 하고 내용을 안 준다.** 실제로 만들어지지도 않는다 → 프롬프트에서 금지하고, `####` 소제목이 없으면 한 번 더 묻는다.
- **`source add` 직후엔 본문이 0자로 잡히고 `source rename` 도 조용히 무시된다** → `source wait` 로 ready 를 기다린 뒤 이름을 바꾼다.
- **`source fulltext` 는 2,000자에서 자른다** → 길이 검증은 `-o FILE` 로.
- **`--notebook <id>` 로 이어받을 수 있다.** 중간에 죽어도 업로드부터 다시 하지 않는다. `--skip-podcasts` 는 팟캐스트를 재사용하고 정리본만 다시 뽑는다.
- **팟캐스트가 한도로 끊겼을 때 `--notebook` 으로 통째로 재실행하면 안 된다.** 정리본 36콜(약 1시간 20분)을 헛되이 다시 뽑고 주차 노트를 덮어쓴다 → 그 경우는 `--podcasts-only`.
- **CLI 응답은 80칸에서 접혀서 온다.** 문장 중간에서 줄이 바뀌면 굵게(`**`)가 두 줄에 걸쳐
  열리고 닫혀 옵시디언이 `**` 를 글자 그대로 뱉고, 접힌 `####` 소제목은 뒷부분이 본문으로
  떨어져 나간다 → `unwrap()` 이 문단 단위로 다시 편 뒤에 나머지를 다듬는다.
- **NotebookLM 은 문장마다 출처 번호(`[1, 2]`)를 붙인다.** 볼트 노트에는 참고문헌 목록이
  없어 숫자만 남으므로 `tidy()` 가 지운다 (W35 노트에서 1,610개 나왔다).
- 모델이 볼트 렌더링 규칙(단독 줄 굵게·굵게 뒤 조사)을 어기므로 `tidy()` 가 노트 기록 직전에 바로잡는다.
- **접는 블록에 `<details>` 를 쓰면 안 된다.** 옵시디언이 그 안의 마크다운을 렌더링하지
  않아 `####` 소제목·불릿·`**` 이 글자 그대로 나오고 줄바꿈까지 뭉개진다 →
  접기 콜아웃(`> [!abstract]- 제목`) 으로 감싼다. 타입 뒤 `-` 가 "접힌 채로 시작"이다.
- **프롬프트 한 콜은 2,700자를 넘기면 안 된다.** NotebookLM 이 `Chat request was rejected
  (status 3)` 로 통째로 거절한다 (실측 2,700 통과 / 3,500 거절). COMMON 은 3콜에 모두
  붙으므로 거기가 길어지면 세 번 다 죽는다 — `PROMPT_LIMIT` 이 넘으면 로그로 경고한다.
- **연동은 Europe PMC 를 다시 조회하지 않는다.** 발송 때 논문 정보를 `last_digest.json` 의
  `papers` 에 같이 저장하고 연동은 그걸 읽는다. 예전엔 연동이 논문마다 EPMC 를 다시 조회했고,
  조회가 실패하면 **경고 없이 그 논문을 빼고** 진행했다 — 2026-09-21(W39) EPMC 503 장애로
  10편 중 1편(PDF 까지 넣어둔 것)이 빠진 노트북이 만들어졌다. 지금은 `papers` 가 없는 옛
  manifest 에서만 EPMC 를 조회하고, 그래도 못 얻으면 디스코드에 알리고 **멈춘다**(`⛔`).
  EPMC 가 죽었는데 당장 돌려야 하면 PubMed E-utilities(esummary+efetch)로 `papers` 를
  손으로 채울 수 있다 (W39 가 그렇게 갔다).
- **주간 종합 브리핑은 만들지 않는다** — 노트 첫머리를 길게 잡아먹고 각 논문으로 바로
  내려가는 걸 방해했다 (2026-08-26).

#### 팟캐스트

`deep-dive` · `--length default` · 한국어. **실측 평균 23분**(11~28분) — `long` 은 21~28분이라 더 길다. 소스가 PDF 전문이라 텍스트로 시험했을 때(13분)보다 길어진다. 64kbps 로 줄여 `MM/paper-digest-audio/<주차>/` 에 두고 원본은 버린다. 주 125MB · 연 6.3GB · 청취 4.5시간.

#### 6편씩 이틀에 나눈다

오디오 생성에는 한도가 있고 이 계정은 **Plus — 24시간에 6편** 이다 (2026-08-31 사용자 확인).
그래서 `PODCAST_DAILY_CAP = 6` 에서 스스로 멈추고, 남은 6편은 다음 날 `--podcasts-only`
실행이 이어받는다. 한도에 부딪히게 두면 그 뒤 논문이 전부 실패로 날아간다.

#### 한도는 "하루 6편"이 아니라 "최근 24시간 안에 6편"이다

리셋 시각이 따로 있는 게 아니라 **각 생성이 24시간 뒤에 하나씩 풀린다** (2026-09-07 확정).
그래서 "내일 아침이면 되겠지"가 통하지 않는다 — 다음 배치는 **직전 배치의 마지막 생성 +24시간**
뒤라야 6편이 다 들어간다.

실측 근거 셋. ① 2026-09-01 은 15:33 막힘 · 17:30 통과였고, 직전 배치가 8/31 17:19 부터였다.
② 2026-09-07 은 13:33~14:29 에 6편을 만든 뒤 **같은 날** 18:58 이 막혔다. ③ 고정 리셋 시각으로는
둘을 동시에 설명할 수 없다 — ②를 설명하려면 경계가 자정(KST)이어야 하는데, 그러면 ①의
09:00 막힘과 17:30 통과가 같은 날이 되어 모순이다.

**실패한 생성과 `artifact retry` 도 슬롯을 먹는다** (2026-09-09 확인 — 전날 3번 생성 중
2번이 실패였는데 다음 날 아침 빈 칸이 3개였다). 그래서 "몇 편 성공했나"가 아니라
"몇 번 요청했나"로 세야 한다.

빈 칸이 언제 몇 개 생기는지는 미리 계산할 수 없으므로 **이어받기를 매일 10:30·17:00 에
두 번 두드린다.** 남은 편이 없으면 즉시 끝나고, 한 편도 못 만든 실행은 디스코드로 알리지도
않는다. 정상 주차는 월요일 6편 + 화요일 17:00 6편으로 끝나고, 이번 W37 처럼 밀린 주차는
며칠에 걸쳐 저절로 채워진다. 월요일 실행을 12:30 에 두는 건 팟캐스트를 13:30~14:40 에
끝내 화요일 오후 빈 칸을 앞당기기 위해서다.

**대신 PDF 를 12:30 까지 넣어야 한다.** 12:00 점검 알림 뒤 여유가 30분이다.
늦으면 그 주는 PDF 없이 URL(초록 범위)로 돌아간다 — 2026-09-07 W37 이 그렇게 됐다.
빠진 PDF 를 채울 시간이 모자라면 점검을 11:00 으로 당기는 편이 낫다
(`com.<you>.paperdigest-notebook-check.plist`).

한도는 요금제를 바꾸면 함께 바뀐다 — `PODCAST_DAILY_CAP` 도 같이 고쳐야 한다.
2026-08-25(W35) 에는 Pro 라 12편이 03:25~06:14 에 한 번에 다 만들어졌다.

`--podcasts-only` 는 **정리본을 다시 뽑지 않는다.** 노트북 id 를 주차 노트 머리말에서 되읽고,
소스를 제목으로 다시 붙인 뒤, 오디오가 없는 논문만 만든다. 한 편 끝날 때마다 주차 노트의 그
논문 자리에 `🎧` 줄을 끼워 넣으므로(`patch_note_audio`) 둘째 날 도중에 또 끊겨도 만든 만큼
남는다. 다 만들어진 주차에 실행하면 즉시 종료한다.

## 설치

1. 이 폴더를 Obsidian 볼트의 `_Tools/paper-digest/` 에 둔다. `notebook_sync.py` 는 두 단계 위를 볼트로 보고 `04_References/Weekly-papers/` 에 주차 노트를 쓴다.
2. 설정 파일 두 개를 복사해서 채운다. 둘 다 `.gitignore` 로 커밋되지 않는다.
   ```bash
   cp config.example.json config.json     # 수신 메일·연구 분야(researcher_context)·카테고리
   cp secrets.example.env secrets.env     # 웹훅·Gmail 앱 비밀번호·API 키
   ```
3. 환경변수(선택)
   | 변수 | 뜻 |
   |---|---|
   | `OPENALEX_MAILTO` | 본인 이메일 — OpenAlex 가 빠른 응답 풀(polite pool)로 받아 준다 |
   | `PAPER_DIGEST_MEDIA` | PDF 드롭·팟캐스트 보관 폴더의 상위 (기본 `~/Desktop/MM`) |
   | `PYTHON` | `run.sh`·`run_notebook.sh` 가 쓸 파이썬 (기본 PATH 의 `python3`) |
4. NotebookLM 연동을 쓰려면 [`notebooklm`](https://pypi.org/project/notebooklm-py/) CLI 가 `~/.local/bin/notebooklm` 에 있어야 한다.

## 카테고리 바꾸기

`config.json` 의 `categories` 편집. 쿼리는 Europe PMC 문법(`TITLE_ABS:"검색어"`).
`researcher_context` 를 고치면 Claude 의 사전선별·관련도 판정 기준이 함께 바뀐다 — 연구 주제가 달라지면 여기부터 손본다.

현재 4개: **장내 마이크로바이옴** · **마이크로바이옴 일반** · **환경독성 × 마이크로바이옴** · **계산·AI 생명과학**.

`계산·AI 생명과학` 쿼리에는 의료 AI 를 막는 `NOT` 절(radiolog·diagnos·clinician·dental·chatbot·nursing 등)이 들어 있다. 이걸 빼면 FDA 규제·진단 챗봇·치과 논문이 다시 밀려든다.

## `quality` 설정

| 키 | 뜻 |
|---|---|
| `candidate_pool` | 카테고리당 후보 수 (기본 100) |
| `exclude_retracted` | 철회·우려표명 논문 배제 |
| `exclude_preprint` | 프리프린트 배제 |
| `exclude_future_dated` | 미래 발행일(ahead-of-print 이슈 날짜) 배제 |
| `one_paper_per_journal` | 한 회차에 같은 저널 1편까지 |
| `min_citations_for_fwci` | 이 인용수 미만이면 FWCI 를 신뢰하지 않음 (기본 5) |
| `prescreen_newest` | 최신 슬롯에 Claude 관련도 사전선별 적용 |

## 문제 해결

- **같은 논문이 계속 온다** — `history.json` 이 지워졌는지 확인. 이 파일이 매주 다른 논문이 오는 유일한 이유다.
- **논문이 12편보다 적게 온다** — 로그의 "신뢰 필터 탈락" 줄을 본다. 후보가 이력에 다 걸리면 예전 발송분을 재사용하므로 보통은 12편이 유지된다.
- **처음부터 다시 받고 싶다** — `rm history.json`. 이력이 비면 예전에 보낸 논문이 다시 온다.
- **저널 지표 없음 경고** — OpenAlex 에 아직 색인 안 된 신규 논문. 정상이며 며칠 뒤 해소된다.
