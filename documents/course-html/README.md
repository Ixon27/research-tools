# 과목 학습노트 → 인터랙티브 HTML

`04_References/Notes/<과목>/`의 학습노트 묶음을 **하나의 self-contained HTML**로 변환한다.
예상문제는 읽기용 텍스트가 아니라 **직접 푸는 문제**로 렌더된다.

> 🔴 **내용은 [`_Tools/html-templates/내용-규칙.md`](../html-templates/내용-규칙.md) 을 따른다.** 이 스크립트는 형식(디자인·레이아웃)만 만들고, 무엇을 어떻게 쓰느냐는 템플릿과 무관하게 그 파일이 정한다 — 특히 §14 정본 대조 · §16 절차 형식 · §17 정본 동기화 · §18 파일명.

## 무엇을 하나
- 왼쪽 사이드바(노트 목록 + 각 노트의 `##` 섹션 + 검색), 본문은 한 번에 한 노트만 표시
- Obsidian 콜아웃(`> [!warning] 시험 포인트`)·표·코드블록·위키링크를 그대로 살림
  (위키링크는 같은 폴더 노트면 클릭 시 그 노트로 이동)
- `## C. 예상문제 …` 절을 파싱해 **보기 클릭 → 정오 표시 + 해설 즉시 공개**
  - 상단 고정 바에 진행률·정답 수·정답률, `전체 초기화`, 문항별 `다시 풀기`
  - 푼 기록은 브라우저 localStorage(`gm-quiz-v1`)에 저장 — 껐다 켜도 유지
  - 스포일러 방지를 위해 원본의 "정답과 해설" 표는 HTML에서 제거된다
- 디자인은 `_Tools/html-templates/designs/notebook.css`를 그대로 인라인(색·폰트 변경 없음),
  학습노트·문제 전용 스타일만 스크립트 안 `EXTRA_CSS`로 덧붙인다

## 사용법
```bash
python3 _Tools/course-html/build_course_html.py                 # 미생물학개론(기본값)
python3 _Tools/course-html/build_course_html.py <노트폴더> <출력.html> [표시제목]
```
기본 출력: 현재 폴더의 `<과목>-학습노트.html`
(HTML은 생성물이므로 vault가 아니라 MM에 둔다. 노트를 고쳤으면 다시 실행하면 된다.)

화면에 뜨는 과목 이름은 `SUBJECT_TITLES` 에서 폴더명으로 찾고, 없으면 폴더명을 그대로 쓴다.
세 번째 인자로 직접 넘겨도 된다.

## 읽기용 — 노트 1편당 페이지 1개

```bash
python3 _Tools/course-html/build_note_pages.py <노트폴더> <출력폴더> [표시제목]
```

한 파일에 다 묶는 위쪽 뷰어와 달리, **노트마다 HTML 하나**를 만든다. 한 편씩 열어 읽거나
인쇄·공유할 때 이쪽이 편하다.

- **번호가 붙은 강의 노트(`01-`~)만** 만든다. MOC·개념 노트는 강의 밖에서 덧붙인 것이라 섞지 않는다
- 사이드바 = 그 노트의 `##` 목차 + 다른 노트로 가는 링크, 본문 아래에 이전/다음 이동
- 위키링크는 같은 세트의 노트면 그 HTML 로 연결되고, 세트 밖이면 글자만 남는다
- `00-목차.html` 을 함께 만든다 — 각 노트의 "핵심 한 줄 요약" 을 뽑아 한 줄씩 붙인 목록
- **JS를 아예 쓰지 않는다.** JS를 막는 뷰어에서도 그대로 보이고, 인쇄용 CSS가 들어 있다
- 문제 노트는 통합 뷰어와 똑같이 **보기를 고르면 정답·해설이 나오는** 블록으로 만든다.
  원본의 정답표는 페이지에서 빠지고, 그 페이지에만 집계·초기화·기록용 짧은 스크립트가 붙는다
  (정오 표시·해설 공개 자체는 CSS라 JS 없이도 풀린다)

실행 예 (마이크로바이옴 분석):
```bash
python3 _Tools/course-html/build_note_pages.py \
  04_References/Notes/Microbiome-Analysis \
  ~/수업/마이크로바이옴분석/노트별
```

## 전제
- `pandoc` 필요 (`/opt/homebrew/bin/pandoc`). 문단 바로 뒤에 붙은 목록도 살리려고
  `lists_without_preceding_blankline` 확장을 켜서 부른다 — 옵시디언은 살리지만
  기본 pandoc 마크다운은 앞줄과 이어 버리기 때문
- 문제 형식은 `**N.** 질문` 다음 줄에 `① … ② … ③ … ④ …`, 정답·해설은 `| N | ③ | 해설 |` 표.
  이 형식은 `/course-study` 산출물 규약과 같다.

## JS 없는 뷰어 대응 (중요)
Dropbox iOS 미리보기처럼 **JavaScript 를 실행하지 않는 뷰어**가 있다. 그런 곳에서도
읽기와 문제풀이가 되도록 만들었다.

- 문제의 정오 표시·해설 공개는 **CSS `:checked` 만으로** 동작한다 (라디오 + label).
  JS 는 점수 집계·localStorage 저장·`전체 초기화`만 얹는다.
- 노트 표시도 JS 의존이 아니다. `<body class="js">` 가 붙을 때만 "한 번에 한 노트"이고,
  JS 가 안 돌면 전 노트가 이어져 보이고 사이드바는 앵커 목록으로 동작한다(모바일에선 본문 위로).
- JS 가 없을 때는 안내 배너(`.nojs-tip`)가 뜨고, 점수 바 등 JS 전용 요소(`.js-only`)는 숨는다.

> 페이지 구조를 바꿀 때 이 두 가지를 깨뜨리지 말 것: ① `.doc` 기본값은 `display:block`
> ② 문제 상태는 `.qr:checked ~ …` 선택자로만 표현.

## 확인된 동작 (2026-08-02, headless Chrome)

- JS 켬: 보기 클릭 → 오답 빨강("선택")·정답 초록("정답") + 해설, 집계 2/60·정답률 50 %,
  localStorage 저장, `다시 풀기`·`전체 초기화` 동작
- JS 끔(스크립트 제거본, 폭 500 px): 노트 전편 표시 + 문제 정오·해설 그대로 동작
- 실제 Dropbox iOS 앱 자체에서는 확인하지 못했다(로컬 재현 불가).
